# SplatScan 规格书

状态：ready-for-agent
适用仓库：splatscan（public，AGPL-3.0）
包名：com.splatscan.app
界面语言：仅中文
基线：minSdk 26，2GB 内存设备可运行

## Problem Statement

想用手机把一个场景变成可自由漫游的三维模型，目前只有两条路都走不通。一类产品（Polycam、Luma、Scaniverse 这类）要么依赖云端上传，要么只在旗舰机上可用，且闭源；另一类开源实现全是桌面或 CUDA 的（OpenSplat、gsplat、LichtFeld-Studio），手机上根本没有能用的端上训练实现，能找到的手机项目全是渲染器。结果是：低端机用户拿不到「拍完就有模型」的体验，也无法在完全离线、不依赖任何外部设备或服务的条件下完成扫描。

现有开源方案还存在两个具体障碍。其一，高斯泼溅的标准流程要求先有相机位姿和稀疏点云（COLMAP 那类工程格式），手机端没有现成可用的位姿来源；其二，训练态内存开销大（每个高斯约 2KB），十万高斯级别就要 200MB，小内存设备很容易被压垮而没有任何降级路径。

## Solution

SplatScan 是一个纯本地的 Android 高斯泼溅扫描应用：用户打开应用即可看到实时摄像头画面，按下开始后用手机环绕场景，采集过程中模型在高斯空间中实时增量生长，主窗口展示的就是最终结果本身，而不是事后的预览；按下暂停时停止采集但后台继续优化已有帧与缓冲帧，画质在等待中提升；按下停止即定格模型，直接可看、可导出。整个过程不联网、不上传、不依赖任何外部应用或设备。

界面遵循 Material Design 3 且保持极简：一个主窗口、一个可选的摄像头小窗、一条由胶囊控件组成的控制栏，以及一条很窄的可展开日志栏。主窗口上用一个白色空心圆环指示当前扫描位置。日志栏收起时优先展示一个由多源数据混合而成的「精度」百分比，让用户一眼判断当前采集质量。

## User Stories

1. 作为扫描者，我想打开应用就直接看到实时摄像头画面，这样我可以马上对准要扫的场景。
2. 作为扫描者，我想只用一个主按钮就能开始扫描，这样我不需要理解任何参数。
3. 作为扫描者，我想在采集中看到主窗口展示正在生长的模型，这样我知道扫描确实在工作。
4. 作为扫描者，我想在采集中把摄像头画面缩成小窗口，这样模型画面能占据主要空间。
5. 作为扫描者，我想在主窗口上看到一个白色空心圆环标出当前扫描位置，这样我像用牙科扫描仪一样知道扫到哪里了。
6. 作为扫描者，我想在按暂停时停止采集但继续优化模型，这样我可以在不动手机的情况下让画质继续变好。
7. 作为扫描者，我想在暂停时看到「正在优化」的进度反馈，这样我知道等待是有意义的。
8. 作为扫描者，我想在按继续时恢复采集，这样扫描可以分多次完成。
9. 作为扫描者，我想在按停止时立刻得到可用模型，这样我不需要额外等待一个训练完成过程。
10. 作为扫描者，我想在扫描过程中看到一条窄日志栏，这样状态信息不占据画面但随时可查。
11. 作为扫描者，我想在采集时看到日志栏收起态显示「精度 0~100%」，这样我可以快速判断当前采集质量。
12. 作为扫描者，我想在未开始和暂停时看到日志栏收起态显示普通状态（帧率、温度、电量消耗、是否充电），这样我知道设备状态。
13. 作为扫描者，我想点击日志栏展开详细日志，这样排查问题时能看到完整过程记录。
14. 作为扫描者，我想让应用自动适配我的设备性能而不需要我设置画质档位，这样我不会因为错误的设置得到糟糕结果。
15. 作为扫描者，我想在小内存设备上也能完成扫描（哪怕高斯更少、画面更糊），这样应用不是我换手机才能用的东西。
16. 作为扫描者，我想在扫描结束后看到模型可以自由旋转和缩放查看，这样我能检查扫得全不全。
17. 作为扫描者，我想把结果导出为 ply，这样我可以在桌面端的通用工具里打开。
18. 作为扫描者，我想把结果导出为 splat，这样我可以在网页查看器里直接看。
19. 作为扫描者，我想把结果导出为 spz，这样我能拿到体积最小的文件。
20. 作为扫描者，我想通过系统分享面板把结果发出去，这样我可以发到网盘或传给电脑。
21. 作为扫描者，我想看到历史扫描列表，这样我可以回看之前的模型而不是只有最后一次。
22. 作为扫描者，我想删除历史扫描，这样存储空间不会一直被占满。
23. 作为扫描者，我想重命名扫描记录，这样我能记住每个模型扫的是什么。
24. 作为扫描者，我想在采集过程中遇到跟丢的情况得到提示，这样我知道要放慢移动或改变拍摄方式。
25. 作为扫描者，我想在设备过热时得到降级而不是被杀掉，这样长时间扫描不会中断。
26. 作为扫描者，我想在充电时获得更高的画质上限，这样我能利用更充足的电力和散热条件。
27. 作为扫描者，我想在未接电源且电量低时被温和提示，这样我不会在扫描中途没电。
28. 作为开发者，我想在完全离线的环境下构建出签名发行版 APK，这样发布流程不依赖我本地的网络状况。
29. 作为开发者，我想让 CI 每次推送都产出 debug 与 release 两个 APK，这样我可以直接拿测试版。
30. 作为开发者，我想让每个可用版本都发到 GitHub Release，这样使用者有稳定的下载来源。
31. 作为开发者，我想让发行签名固定不变，这样用户可以在版本间覆盖安装。
32. 作为开发者，我想让精度指标的计算逻辑可单元测试，这样我调整权重时不会引入回归。
33. 作为开发者，我想让自适应调节逻辑可单元测试，这样我不用真机就能验证降级策略。
34. 作为开发者，我想让模型与记录存取逻辑可单元测试，这样我不会因为改存储格式弄坏历史数据。
35. 作为开发者，我想让导出格式做到读回一致，这样跨版本兼容性有保障。
36. 作为开发者，我想让界面状态机可单元测试，这样按钮在不同状态下显示什么不需要靠真机验证。
37. 作为使用者，我想让应用不申请任何多余权限（只要摄像头），这样我对隐私放心。
38. 作为使用者，我想让应用完全无网络权限，这样我确信扫描数据不会被上传。
39. 作为使用者，我想让所有扫描结果存在应用自己的目录里，这样卸载即清理干净。
40. 作为使用者，我想让界面只有中文，这样文案不会出现半截英文。
41. 作为使用者，我想让界面遵循 Material Design 3（动态取色、深浅色、边到边），这样它看起来是系统的原生应用。
42. 作为使用者，我想在小窗口里看到摄像头画面，这样我拍的时候不用在两个视图之间切换。
43. 作为使用者，我想让应用在我旋转屏幕后不丢失扫描进度，这样误操作不会毁掉一次扫描。
44. 作为使用者，我想让应用在返回后台时暂停采集并在回前台后恢复提示，这样我不会在不注意时把什么都扫进去。
45. 作为使用者，我想让模型视图支持双指缩放与单指拖动，这样操作方式和常见三维查看器一致。

## Implementation Decisions

### 平台与工程

应用为纯原生 Android，Kotlin + Jetpack Compose + Material 3，不使用 Unity、WebView 或跨平台框架。模板工程已含 Compose Material3 与 ARM64 aapt2 替换脚本，包名与应用名改为 com.splatscan.app 与 SplatScan。仅声明摄像头权限，不声明任何网络权限。全部扫描结果写入应用私有目录，导出时才通过系统分享面板离开应用。

基线定为 minSdk 26，2GB 内存设备可运行。渲染主路径为 Vulkan 1.1（compute shader 完成高斯光栅化与球谐着色），在没有可用 Vulkan 1.1 设备时回退到 OpenGL ES 3.1 简化路径。

### 运行时三方来源

相机画面由 Camera2 拿到 YUV 帧，交由原生层处理。位姿自己实现视觉惯性里程计，不依赖 ARCore，也不使用纯 IMU。理由是加速度计二次积分在几十秒内会产生米级漂移，无法支撑高斯重建所需的厘米级位姿；视觉提供主体运动，IMU 提供尺度、重力方向与快速运动时的补位。

### 训练与渲染内核

训练器自写，不引入 libtorch 与 OpenCV（它们在 Android 上体积与内存开销都不可接受）。算法与 CPU 光栅化思路参考 OpenSplat（AGPL-3.0），球谐与稠密化策略参考 splatfacto（Apache-2.0）的做法。顶点拟合使用轻量线性代数实现。spz 压缩采用 OpenSplat 中 vendored 的独立 spz 库。

内存预算是设计的第一约束：训练态每高斯约 2KB，因此高斯数量上限由可用内存决定，低端机天然得到更少的点与更糊的画面。训练图像按设备能力动态降采样。

### 增量与暂停语义

采集期间每个关键帧批次触发少量迭代，模型在高斯空间中持续生长，主窗口展示的就是最终结果。暂停的语义是停止采集新帧，同时把缓冲区里尚未并入的帧全部并入优化并持续跑迭代，日志显示优化轮次与预计剩余时间。继续即恢复取帧。停止即终止一切计算并定格结果。

视频帧在会话结束后不保存，仅作为优化素材。

### 自适应策略

不使用任何固定阈值闸门做画质分级。运行时常量地测量帧率、可用内存、设备温度、电量消耗速度与供电状态，据此连续地调节抽帧密度、训练迭代量与高斯数量目标，使负载保持在设备可持续的水平。判定逻辑集中在单一的调节器组件里，输入是遥测快照，输出是当前规格档，便于单元测试。

### 界面结构

未开始时主窗口显示摄像头画面，没有小窗口，控制栏显示「开始」小胶囊与「日志栏」大胶囊。采集与暂停时主窗口显示模型，小窗口显示摄像头画面，主窗口上覆盖白色空心圆环指示当前扫描位置。控制栏在采集中显示日志栏、暂停、停止；在暂停中显示继续、停止、日志栏。

日志栏是很窄的一条，点击后展开为详细日志列表。收起态在采集中优先显示精度百分比，在未开始与暂停时显示普通状态行。

### 精度指标

精度是一个 0~100% 的综合分值，由多源数据混合而成，用于概要反映当前采集的质量与效果，其输入包括位姿跟踪的稳定程度、已覆盖视角的充分程度、重建残差水平以及模型规模是否受内存压制。该计算必须是可以脱离设备运行的纯函数，便于测试与调参。

### 记录与导出

每次扫描产出一条记录，包含模型数据与元信息（时间、时长、高斯数量、平均精度）。模型查看页支持单指拖动旋转、双指缩放。导出支持 ply、splat、spz 三种格式，通过系统分享面板发出。

### 测试缝

优先复用已有缝，尽量少。计划中的缝有三个：一是原生核的 JNI 表面（相机帧、IMU 数据、控制指令进出，状态快照出来），二是纯 Kotlin 的遥测与规格调节器，三是纯 Kotlin 的记录存取与格式编解码（含精度计算与界面状态机）。

## Testing Decisions

好测试的标准是只验证外部行为：给定输入断言输出与可观察状态，不依赖内部实现细节、不依赖真机、不需要等待真实时间流逝。

计划测试的模块包括遥测调节器、精度指标计算、扫描记录存取、格式编解码往返、以及界面状态机（哪个状态下哪组按钮可见、日志栏显示哪一类内容）。前四项用 JVM 单元测试，界面状态机用纯状态对象做单元测试而不启动 Activity。

原生核不以单元测试覆盖，而是提供一个可从仪器化测试或调试入口调用的自检路径：加载空模型、跑若干步迭代、输出状态快照，验证数值不产生 NaN 且高斯数量单调增长。缺少真机时该测试允许跳过。

## Out of Scope

不做云端上传与账号体系。不做网格（GLB/OBJ）导出与网格重建。不做多人协作与分享链接。不做 AR 叠加显示与平面检测。不做 iOS 与桌面端。不做英文与其它语言界面。不做设置页与手动画质档位选择。不做扫描过程中的视频文件保存。不做模型编辑（裁剪、擦除、减面）。

## Further Notes

精度指标与自适应调节器是本项目最容易被做砸的两处：前者容易被做成一堆互相矛盾的读数，后者容易被做成一堆固定阈值。两者都按「单一组件、纯函数、可测试」来约束。

渲染性能是整个方案的可行性闸门：如果低端机上 Vulkan compute 光栅化的帧率不足以支撑采集时的实时预览，实时增量方案就需要退回到更保守的更新频率，这一点在第一个可安装版本里就要验证。
